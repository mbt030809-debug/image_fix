# 체형 보정 (다듬기 → 체형) — v2.0.0 · 경계 자동 맞춤 v2.1.0

## 목표
얼굴·몸 비율을 고치되 **배경이 일그러지지 않게**. 기존 리퀴파이는 사진 전체를 밀어서 배경 선이 휜다.

## 방식
1. **인물만 변형**: 올가미/브러시로 인물을 고르고, 변형은 "되돌려 찾기(backward mapping)"로 인물 픽셀과 *새 인물 마스크*를 만든다. 배경은 건드리지 않는다.
   - **폭**: 흰 선 두 줄 사이(위·아래 25% 구간은 부드럽게 0 → 가운데 1)에서 행마다 인물의 가로 중심을 기준으로 가로 배율(±15%).
   - **길이**: 밴드 안을 세로로 늘이거나 줄이고(±15%) 밴드 아래 내용은 따라 이동(위쪽은 고정).
   - **확대·축소**: 한 점 주변의 방사형 확대/축소(±40%) — 눈·코·턱 같은 작은 부분.
2. **드러난 배경 채우기**: (예전 인물 마스크 ∪ 새 인물 마스크)를 조금 키운 "바뀌는 곳"을 모르는 영역으로 보고, 바깥의 알려진 배경 색을 피라미드(push-pull)로 번지게 채운 뒤, 둘레 입자감과 같은 세기의 노이즈를 더한다. 인물이 커지는 쪽은 배경을 덮기만 한다.
3. **합성**: 결과 패치는 "바뀌는 곳"만 불투명, 나머지는 **완전 투명** → 레이어로 얹어도 그 밖의 배경은 한 픽셀도 바뀌지 않는다(단위 테스트·E2E 로 확인). 가장자리 2px 는 원본 색 그대로 번지게 섞는다.
4. **레이어**: 잠긴 이미지 레이어("체형 보정", `fx.kind = body`) — 숨기기·삭제·실행 취소·자동 복구. 여러 조절("이 조절 추가")을 쌓아 한 번에 적용한다. 도구를 나가면 미리보기는 버려지고 "적용"으로만 확정된다.

## 사용
다듬기 → 체형 → ① 인물 선택(몸 선을 따라 그리기) → ② 조절(폭/길이/확대·축소, 위·아래 선 · 강도) → 적용. 미리보기는 낮은 해상도로 실시간, 적용은 영역을 최대 1400px 로 다시 렌더해 계산한다.

## 인물 경계 자동 맞춤 (v2.1.0, `web/src/ai/autoselect.js`)
올가미를 **힌트**로 쓰고 실제 경계는 이미지가 정한다. 모델 파일 없이 오프라인으로 동작한다.
1. 올가미 안쪽 깊은 곳 = 확실한 인물, 바깥 깊은 곳 = 확실한 배경, **선 주변 띠(긴 변의 4%, 고정)** = 미확정.
2. 확실한 두 영역의 색 히스토그램(4비트·3비트 평균)으로 띠 픽셀의 인물/배경 점수를 매긴다. 올가미에서 멀수록 올가미 라벨을 선호하는 사전 확률을 더한다.
3. 이웃 픽셀 색차가 큰 곳(가장자리)에서 자르기 쉽게 8-이웃 가중치를 두고 **그래프 컷(Dinic 최대 흐름)** 으로 띠 전체를 한 번에 푼다. 480px 해상도에서 계산 후 선택 격자로 확대·부드럽게.
4. 작은 섬/구멍 정리. 결과가 올가미와 너무 다르거나(면적 50% 미만·160% 초과), 두 색 분포가 겹치면(인물·배경이 같은 색) **올가미 그대로** 쓰고 안내 토스트를 띄운다.
- 사용: 인물 선택 단계 → 올가미(자동 맞춤 켜짐/꺼짐 스위치). 브러시는 자동 맞춤 없음. 선택 되돌리기로 한 번에 취소.
- 추가/빼기 스위치는 유지(v2.2.1 의 통합 방식은 되돌림). "맞춤 범위"·"경계 부드럽게" 슬라이더는 의미가 모호해 없앴다(각각 4%·기본값 고정).
- **띠 밖은 건드리지 않는다**: 올가미가 몸에서 맞춤 범위보다 멀리 떨어진 곳(예: 머리 옆 빈 배경)은 그대로 선택된다 — 몸 선을 따라 대충 그리되 너무 크게 벗어나지 않게. 틀린 곳은 빼기/브러시로 고친다.
- 한계: 머리카락 끝·배경과 색이 비슷한 경계·그림자는 틀릴 수 있다. 자동 인물 분리(AI 모델)는 아니다.
- 테스트: `node web/tests/autoselect.unit.mjs`(13: 넉넉/파고듦/비뚤게/정확/색 구분 불가/경계 조건), `node tests/e2e/autoselect.cjs`(합성 인물 사진에서 느슨한 올가미 IoU 0.74 → 0.98, 꺼짐·되돌리기·빼기).

## 인물 분리 모델 (v2.2.0, `web/src/ai/person.js`)
색 기반 맞춤(v2.1.0)이 경계를 잘 못 찾아 **기기 안에서 도는 인물 분리 모델**을 더했다.
- 모델: U²-Net-P(4.5MB) + ONNX Runtime Web(wasm 단일 스레드, 11MB) — 앱에 포함, **인터넷 불필요, 사진이 기기 밖으로 안 나감**. APK 가 약 3.6MB → 약 14MB 로 늘었다.
- 흐름: 사진을 320px 로 줄여 모델 실행(도구를 연 뒤 처음 한 번, 데스크톱 헤드리스 약 2.5~3.7초 · 이후 즉시) → 피사체 맵 → **올가미 주변 범위로 제한 + 가장 큰 덩어리/올가미와 겹치는 덩어리만** → 색·가장자리 맞춤(`refineMask`)으로 480px 에서 경계 다듬기.
- **인물 자동 선택** 버튼: 올가미 없이 가장 큰 피사체를 한 번에 선택.
- 올가미: 모델이 올가미 안에서 인물을 못 찾으면(20% 미만) 색 맞춤으로, 그것도 못 믿으면 그린 대로 선택(토스트로 어느 방식인지 알림). 모델 로딩/실행이 실패해도 앱은 멀쩡하다(E2E 로 모델 요청을 막고 확인).
- 한계: 사람 전용 모델이 아니라 **주요 피사체(salient object)** 모델이다 — 사진에 큰 물체·동물이 있으면 그걸 고를 수 있고, 여러 사람은 한 덩어리로 잡힐 수 있다(올가미로 한 사람만 둘러 제한). 아주 작은 인물·복잡한 배경은 약하다. 모델 해상도가 낮아 머리카락 끝은 뭉툭할 수 있다(색 맞춤으로 일부 보정).
- 검증: 실제 사진 3장(손 든 인물·뒷모습·바다 배경)에서 윤곽이 정확했다(수동 확인). 자동 테스트는 `tests/e2e/person.cjs`(실제 사진 1장 + 모델 차단 대체), `web/tests/autoselect.unit.mjs`(20).

## 경계 정밀화 (v2.3.0, `web/src/ai/edgesnap.js`) — 평가 결과
**구조**: 모델(320px)은 거칠게 한 번만 → 경계 띠(긴 변의 약 1.2%)만 **작업 해상도(최대 1024px)** 에서 다시 판정.
1. Canny(블러 → Sobel → 비최대 억제 → 이중 임계값·히스테리시스)로 "자르기 쉬운 선"을 구함.
2. 색 히스테리시스 + Canny 가장자리 + **모델 확률(한 표)** 을 합친 그래프컷으로 띠 안을 인물/배경 확정.
3. 인물 안쪽의 작은 구멍 메우기, 가이디드 필터로 띠 안의 알파(반투명 경계).
4. 올가미: 모델이 올가미 안에서 인물을 잘 찾았으면(15% 이상) 모델을 믿고 올가미는 범위 제한으로만 사용(넉넉한 올가미 OK), 못 찾았으면 올가미를 힌트로(깊은 안쪽=인물) 사용.

**평가 방법** (`tests/eval/`, 개발 전용 — 사진은 저장소에 넣지 않음)
- 실제 사진 4장(올려주신 사진 1장 포함) + 어려운 배경 합성 12장(같은 인물을 머리색과 비슷한 어두운 배경·피부색 배경·알록달록한 잡다한 배경에 합성 — 정답을 정확히 앎).
- 실제 사진의 기준(정답 대용)은 isnet-general-use(179MB, 앱에는 넣지 않음)의 결과다 — **사람이 그린 정답이 아니므로 절대 수치가 아니라 비교용**으로만 본다.
- 지표: 경계 F-score(허용오차 ≈0.3%), IoU, 평균 경계 거리 오차(px), 시간(Node, 1 스레드).

| 방식 (자동 선택) | 합성 12장 IoU / F / 오차px | 실제 4장 IoU / F / 오차px | 시간 |
|---|---|---|---|
| 모델 확률 0.5 만 | 0.832 / 0.731 / 4.56 | 0.892 / 0.776 / 5.64 | 0 |
| **이전 앱(v2.2.x)** | 0.833 / 0.701 / 4.50 | 0.924 / 0.646 / 4.00 | 약 60ms |
| **새 방식** | **0.854 / 0.783 / 3.44** | 0.897 / 0.763 / 5.71 | 약 270ms |

| 방식 (올가미 3% 넉넉) | 합성 | 실제 |
|---|---|---|
| 이전 앱 | 0.834 / 0.703 / 4.59 | 0.924 / 0.646 / 4.00 |
| **새 방식** | **0.903 / 0.793 / 3.03** | **0.943 / 0.790 / 3.15** |
(올가미 8% 로 아주 넉넉하게 그려도 새 방식 F 0.76~0.78 — 이전 앱 0.65~0.70)

- 새 방식이 이전 앱보다 경계 F 가 합성에서 +0.08, 실제에서 +0.12~0.14. 시간은 +약 200ms(Node 기준).
- 자동 선택은 실제 사진에서 모델만 쓸 때(0.776)와 비슷하다 — **한계는 모델의 의미적 누락**(예: 한 장에서 왼팔·가방을 인물로 보지 않음)이지 경계 위치가 아니다. 이 경우는 올가미로 보완.
- 잘못 설계했다가 고친 것(평가로 발견): 경계 띠에 모델이 애매한 곳을 몸 깊은 곳까지 넣자 흰/회색 옷이 배경으로 잘려 나감 → 경계 근처(띠 폭의 2.5배)로 제한 + 모델 확률 한 표 + 구멍 메우기.

**시도했지만 채택하지 않은 것 (측정 결과)**
- **모델 int8 양자화**: 동적 양자화는 CPU 에서 오히려 2배 느림(918ms vs 450ms). 정적 양자화(보정 사진 10장)는 크기 4.5→1.3MB, 속도 408→260ms(약 1.6배)이나 결과 IoU 가 fp32 대비 0.86~0.95 로 떨어짐(보정 사진 기준, 낙관적). 정확도 손실이 커 채택하지 않음.
- **턱선 인식**: 올려주신 사진에서 Canny + 타원 맞춤을 시도 — 턱 경계가 피부색과 거의 같아 엣지가 희미하고 코·선반 선에 걸려 실패. Haar 얼굴 박스도 턱 아래까지 잡혀 정확하지 않았다. 얼굴 랜드마크 모델(FaceMesh/PFLD 등)이 필요하며 이 환경에서는 받을 수 없어 미구현.
- **추론 Web Worker 이동**: 미구현(UI 멈춤 완화 목적이라 정확도와 무관, 실기기에서 확인 후 결정).

## 한계(솔직하게)
- **배경 채우기는 단순 배경(단색·그라데이션)에 가장 잘 맞는다.** 선·무늬·사람이 있는 배경에서는 채운 띠가 티 날 수 있다(무늬 이어붙이기·AI 채우기는 아직 없다). 너무 많이 줄이면(±15% 한도) 띠가 넓어져 더 티 난다.
- 인물 선택의 품질이 결과를 좌우한다 — 머리카락처럼 경계가 복잡하면 마스크를 손으로 다듬어야 한다. 경계는 인물 분리 모델(v2.2.0) + 색·가장자리 맞춤으로 잡지만 완벽하지 않다.
- 몸이 자연스러운지(관절·옷 무늬 비율)는 사용자가 판단한다. 한 번에 크게 하지 말고 조금씩 쌓는 것을 권한다.
- 실기기에서 확인하지 못했다(합성 샘플 사진과 헤드리스 브라우저로만 검증). 큰 사진은 영역을 1400px 로 줄여 계산한다.
